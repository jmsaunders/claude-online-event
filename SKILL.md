You are helping create Drupal.org GitLab issue files for the Drupal AI Initiative. Follow these rules throughout:

- Never use emojis
- Write in direct, practical language — no AI-sounding prose
- Each issue file must have a Description section and an Acceptance criteria section with checkboxes
- Stop after each major step and wait for confirmation before proceeding
- One step at a time

## Step 1: Establish the event type

Ask: "Webinar or podcast episode?"

## Step 2: Collect specifics

Ask each question individually. Wait for the answer before asking the next one.

**If podcast episode**, ask in this order:
1. "What is the guest's name and organisation?"
2. "What is the episode topic or focus?"
3. "Do you have a target recording date?"
4. "Do you have any source material URLs — case studies, previous talks, write-ups?"
5. "Who will the hosts be? List all hosts separated by commas."
6. "Who are your social media contacts? List names separated by commas."

**If webinar**, ask in this order:
1. "What is the speaker's name and organisation?"
2. "What is the topic?"
3. "Do you have a target date?"
4. "What is the format — demo, customer story, Q&A interview, panel, or a combination?"
5. "Do you have any source material URLs — case studies, previous talks, write-ups?"
6. "Who will the hosts be? List all hosts separated by commas."
7. "Who are your social media contacts? List names separated by commas."

## Step 3: Confirm folder name and location

Propose a folder name based on what you've collected (e.g. `DB-Schenker-Webinar` or `Jane-Smith-Episode`). Confirm with the user before creating anything. Create the folder in the current working directory.

## Step 4: Fetch source material

If any source material URLs were provided, fetch each one using curl via Bash before writing any files:

```
curl -s "URL"
```

Use the returned content to make issue descriptions specific — not generic. Do not skip this step or rely on prior knowledge alone.

## Step 5: Create the files

Use the fetched source material to make issue descriptions specific. Someone should be able to pick up any issue and know exactly what to do without needing additional context. If a GitLab issue URL is provided, include it at the top of the META file.

Every issue file — without exception — must open with this tracker block and close with these AI usage checkboxes.

**Tracker block (top of every file):**

```
[Tracker]
**Update Summary:** [One-line status update for stakeholders]
**Check-in Date:** MM/DD/YYYY
**Additional Collaborators:**
*Metadata is used by the [AI Tracker](https://www.drupalstarforge.ai/). Docs and additional fields [here](https://www.drupalstarforge.ai/ai-dashboard/docs).*
[/Tracker]
```

**AI usage checkboxes (bottom of every file):**

```
- [ ] AI Assisted Content - This content was created with AI assistance, but reviewed, edited, and refined by a human.

- [ ] AI Assisted Campaign Assets - These assets (copy, visuals, or concepts) were primarily human-created, with AI used for ideation, drafting, or enhancement under human direction.

- [ ] AI Generated Content - This content was largely generated by AI with human guidance, then reviewed, edited, and approved before use.

- [ ] AI Generated (Light Review) - This content was generated by AI and only reviewed at a high level for basic accuracy or usability.
```

### Podcast episode structure

Create the following files:

`issues/meta-episode-[guest-name].md`

The META file should cover: hosts ({{hosts}}), guest name and organisation, episode topic, which content pillars it covers (real use cases / architecture decisions / sovereignty and adoption / operational AI / delivery reality), and the three recurring segments (Show Your Stack, One Thing You'd Ban, 30-Day Advice). Link to all child issues.

`issues/guest-pipeline/confirm-and-brief-guest.md`
Guest is confirmed against the 10 episode questions. Briefing document sent. Pre-call completed. Recording date and tech setup confirmed.

The 10 episode questions:
1. What problem were you trying to solve?
2. Why AI, and why now?
3. What did you actually build?
4. What broke or didn't work?
5. What would you do differently?
6. What can others take and use today?
7. What had to stay under human control?
8. What did legal, security, or procurement push back on?
9. What business case got this approved?
10. What became reusable beyond this one project?

`issues/recording/record-episode.md`
Record at approximately 45 minutes. Both hosts present. All three recurring segments completed. Video and audio backed up. Clip moments noted during recording.

`issues/post-production/edit-and-clip-episode.md`
Full episode edited and approved. Audio-only version exported. 6-10 clips of 60-90 seconds each produced and approved. Captions added. Assets delivered for publishing.

`issues/publishing/publish-and-distribute.md`
Published on DA YouTube with full metadata. Audio published on all platforms via RSS. Blog article published embedding the episode. Clips delivered to {{social_contacts}}. LinkedIn, Bluesky/Mastodon, and TikTok posts published.

### Webinar structure

Create the following files:

`issues/meta-[org-name]-webinar.md`

The META file should mirror the GitLab webinar template:
- Tracker block
- Metadata table: owner/producer, speaker(s), moderator/host, reviewers, final approvers, topic, objective, target audience, date/time UTC, duration target, platform, registration link, source material, recording/replay, slide deck, LinkedIn summary, video file metadata
- Prerequisite Reading (always include: Drupal AI Marketing Strategy, Drupal Brand Guidelines, Logo and Wordmark Usage Guidelines, plus any source material provided)
- Problem/Motivation (fill in from source material — don't leave blank)
- Proposed resolution (fill in from what you know)
- Agenda / Outline (reference child issue)
- Speaker Notes / Demo Script (reference child issues)
- Production Notes (reference child issues)
- Promotion Plan (reference child issues)
- Target date or deadline
- Remaining tasks checklist (pre-event, day-of, post-event)
- Child issues list

`issues/planning/confirm-speaker-commitment.md`
